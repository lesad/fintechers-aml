## [Unreleased]

### Added

- `engine/`: alert summary. `POST /api/alerts/{id}/summary` collects the alert's activity (its rule hits aggregated per rule in code, and its triage decision with the scoring reasons), asks Sonnet 4.5 on Bedrock for two or three sentences through a fixed JSON schema, checks that every sentence cites only refs from that activity and writes only numbers from the input, and stores it in `alert_summary` with the model id and prompt hash; `GET` returns the latest. `Bedrock.askJson` adds structured outputs to the Bedrock client.
- Engine `GET /api/transactions` (paged review queue of flagged transactions, with search, rating filter and counts per rating) and `GET /api/transactions/{id}` (transaction, client, alerts with evidence, the client's transactions), in `engine/.../transaction/`. The rating is a provisional rule (B or C → High; A → Medium, Low for a low-risk client) until it reads the engine's triage disposition (`alert_triage`).
- The review queue and the transaction detail read the engine instead of mock data: infinite scroll with a loading row under the table (`LoadMore`), search and rating filtered on the server, thresholds and actual values computed from each hit's evidence, loading and error states in the detail. `pnpm dev` proxies `/api` to the engine. The mock data is gone; the AI part of the rating shows "Not assessed" (no model rates cases, ADR-0032).

- `docs/GLOSSARY.md`: one meaning per term for the pipeline (detect, triage, review, assist, tune), built on the engine's own terms (ADR-0032).
- `engine/`: Bedrock client. Inject `Bedrock` and call `ask(system, prompt)` for a one-shot text answer through the Converse API (`eu-central-1`, default model `eu.anthropic.claude-sonnet-4-5-20250929-v1:0`, override with `BEDROCK_MODEL_ID`). Credentials come from the default AWS chain: `aws sso login --profile hackathon` and `AWS_PROFILE=hackathon`. A reasoning block before the answer (gpt-oss) is skipped.
- `engine/`: HTTP API. `./gradlew bootRun` without a command serves `GET /api/alerts` (latest run, `?runId=` for another) and `GET /api/alerts/{id}`. `import` and `run` still run and exit.
- `engine/`: deterministic alert triage (ADR-0033). Every alert gets a disposition — `AUTO_CLOSE`, `REVIEW_LOW`, `REVIEW_MEDIUM`, `REVIEW_HIGH`, `ESCALATE` — scored in code from the rules that fired and the client's risk factors, with no model and no clock. Decisions land in `alert_triage` with their reasons, `config_version` and a SHA-256 `input_hash`, and the alerts CSV gains `disposition` and `score`. `./gradlew bootRun --args=triage` re-triages a stored run under a changed config. Weights, bands, the auto-close whitelist and the floors are versioned data in `resources/triage/triage-config-v1.json`.
- `engine/`: the rules engine. `./gradlew bootRun --args=import` loads the ČNB data into Postgres (amounts in haléře, FX by ČNB fixing, prorated Q2 baseline); `--args=run` runs the CEL rules A1–A3, B1–B2 and C1 (company layer) into hits, alerts (A per client, B per transaction, C per client) and `data/out/alerts-<run>.csv`. July data: A 5,493, B 112, C 1,077. Run instructions in `engine/README.md`.
- The AML review queue, first page of the UI, built from `docs/design/aml-review-queue` on mock data: header (open cases by rating, open a transaction by ID with ⌘K / Ctrl+K), tabs (the queue plus closable transaction tabs; detail content comes next) and the queue table with search, rating and status filters. The page always fits the window; only the table body scrolls, under a sticky header. Design tokens (MoroSystems palette, risk colours, Inter Tight) live in `src/app/globals.css` as Tailwind `@theme` values.
- The transaction detail, built from `docs/design/aml-review-queue` on mock data: a fixed strip (transaction, amount, payer → payee, case status), the rule and AI ratings side by side, the day's money flow as an SVG (payers → client's account → payees, line width = amount), the client's recent transactions with earlier flags, a sticky client card with Q2 expected vs real volume, and the decision (close or escalate with a required reason, undo). A decision updates the queue and the header counts. Detail tabs stay mounted while hidden, so a draft reason and the scroll position survive a tab switch.
- `cva` (class-variance-authority) for component variants (ADR-0031), and `Card`, `RiskBadge`, `AiPill` as components.

### Changed

- `src/middleware.ts` → `src/proxy.ts` (default export renamed `middleware` → `proxy`; test renamed with it). Next 16 renamed the file convention — the old name still builds but emits a deprecation. The `proxy` runtime is always `nodejs` and cannot be configured; both things the file does (next-intl middleware, Supabase `updateSession`) run on node. An app needing the `edge` runtime must stay on `middleware.ts`. `@/supabase/middleware` keeps its name — it's our own helper, not the Next convention. See ADR-0018.
- `typedRoutes` moved out of `experimental` (stable in Next 16), and `experimental.globalNotFound` removed — measured to be a **no-op** on 16.2.4: `app/global-not-found.tsx` returns 404 with its localized copy with the flag absent, in `pnpm dev` and against `pnpm build`/`pnpm start`, route table unchanged. The comment claiming the flag enabled the file was false and is corrected. See ADR-0018 (amends ADR-0013).
- Unit vitest project: `isolate: false` → `true`. Sharing one module registry across a worker's files makes two files mocking the _same_ module collide — first factory wins for both — so it passes locally and fails in CI pointing at the other file. `pool: "threads"` + `fileParallelism: true` unchanged. See ADR-0017.
- The `storybook` vitest project is gated behind `STORYBOOK_TEST`. `storybookTest` loads Storybook's main config at _config_ time, so every `vitest` run — even `--project=unit` — booted Storybook: ~2.2s of overhead on a run whose unit tests take 0.3s. See ADR-0017.
- Playwright: local workers capped at 2 (`CI ? "50%" : 2`), local reporter `dot`, and the dev server's `stdout`/`stderr` ignored outside CI. CI runs a compiled production build; a local run is `pnpm dev`, where Turbopack compiles per route on first hit and ~5 parallel workers stall navigations past any assertion timeout — 1-4 rotating failures per run, each passing in isolation. Two workers is green _and_ faster; raising timeouts does not fix it. See ADR-0017.
- oxlint's test relaxation block now covers `*.spec` and `*.e2e` (it listed only `*.test`/`*.stories`/`tests/**`/`src/core/test/**`, so this repo's own integration specs and Playwright tests were held to production rules) and turns off `no-await-in-loop` there. See ADR-0019.
- `tsconfig.json` `target`/`lib` ES2022 → ES2023 (Node ≥24 is already the declared engine).
- `src/core/test/ids/tree.ts`: `TestIdNode` is a `type`, not an `interface` (per the new rule). Its `Object.entries` cast now routes via `unknown` — with a `type`, TS widens the entry value to the union of the declared members, which doesn't overlap `TestIdNode`.
- Guestbook now consumes the Zod i18n layer end-to-end and demonstrates two custom-error kinds (See ADR-0013): a custom `.refine` (no links → `validation.custom`) with `zodErrorMap(t)` passed per parse on both the server action (`safeParse`) and the client (`zodResolver`); inline schema `.min` messages dropped (they overrode the map). `GuestbookFormState` splits per-field `fieldErrors` from an optional typed `formError` domain code (`"unexpected"`, set when the write throws) rendered as a translated `guestbook.errors.*` message; the blanket `guestbook.submitError` key is gone.
- Relocated the `guestbook` slice into `src/features/guestbook/` — components, schema, stories, `actions.ts`, data-access `queries.ts` (moved out of `core/db/queries/`), and co-located tests now live together; the route keeps only `page.tsx` and `src/components/` is purely reusable shadcn `ui/`. Fixes a backwards dependency where the reusable form imported its action-state type from the route. `core/db/queries/` is removed — `core/db` is now the Drizzle client + central schema (the shared relational model, reached via `@/db`); feature queries import `{ db, <table> }` from `@/db`. Eject manifest simplified (the eject-invariant `core/db/index.ts` + placeholder `queries/index.ts` dropped from the restore map). See ADR-0011.
- Consolidated `src/{db,test,lib,testids}` into `src/core/` as one module per concern — folders with an `index.ts` public API (`db`, `hooks`, `i18n`, `supabase`, `test` incl. `test/ids`, `utils`) plus the flat `env.ts`; top-level `src/` is now exactly `app/`, `components/`, `core/`, `docs/` (+ Next-required `middleware.ts`). Every core module has a **bare tsconfig alias** (`@/db`, `@/env`, `@/hooks`, `@/i18n`, `@/test`, `@/utils`; `@/supabase/client|server`) — imports go through the module root, never `@/core/…` or deep internal paths. Removed the `src/i18n.ts` shim. See ADR-0007.
- Tests may be grouped into a `__tests__/` sibling folder when they crowd out a folder's source (~3+); the `.test`/`.spec`/`.e2e` suffix stays required (discovery globs + the unit/integration/e2e project split are suffix-based, not folder-based). Applied to `src/core/test/ids/`.
- `docs/superpowers/` is now gitignored — agent branch-runtime docs and plan drafts, never committed (per ADR-0004); untracked the previously-committed design spec.
- CI `fallow` job now posts a sticky PR comment + Fallow Check Run (`comment: true`, with `pull-requests`/`checks` write permissions) so findings are prominent, not just inline annotations (GitHub caps those at 10 per type per step).

### Fixed

- `.fallowrc.json` reaches **zero findings**, so its rules moved from `warn` to `error` and the CI job is now a real gate rather than advisory noise. The `warn` level had been masking a set of framework-invisible graph roots — files nothing `import`s because a framework, bundler, or the TS compiler loads them by path or by name:
  - **Entry points added.** `src/proxy.ts` replaces the stale `src/middleware.ts` (renamed per ADR-0018 — the old glob matched nothing, so the proxy wasn't a graph root at all). `src/core/i18n/request.ts` (loaded by the next-intl plugin), `src/core/test/server-only-stub.ts` (a vitest `alias` target), `global.ts` (TS module augmentation), `src/core/supabase/{client,server}.ts` (no barrel by design, per ADR-0007/0012), and `src/core/*/index.ts` — the core modules' public API, the same category as the already-listed `src/features/*/index.ts`: on a template these barrels are the surface consumers import, so "nothing imports it yet" is the intended state, not dead code. `**/*.e2e.ts` scoped to `src/**/*.e2e.ts`.
  - **`ignoreDependencies`:** `@swc/plugin-react-remove-properties` (referenced as a **name string** in `next.config.ts` `experimental.swcPlugins` — wasm SWC plugins are resolved by name, never `import`ed) and `@storybook/addon-docs` (config-only, like the other addons already listed).
  - **`ignorePatterns`:** `src/docs/**` (MDX transcluded into Storybook, not part of the module graph).
  - **`ignoreExports`:** Next's route-segment config exports (`dynamic`, `revalidate`, `runtime`, `maxDuration`, the `alt`/`size`/`contentType` image-metadata trio, …) under `src/app/**` — read by the framework off the module record, so they never appear as an import.
  - **`health.ignore`** (configs, `scripts/**`, `src/core/test/**`, `**/*.e2e.ts`) and **`duplicates.ignore`** (`src/app/globals.css`) keep complexity/duplication signal on application code.
- The commit gate no longer runs on non-commit commands: `.claude/hooks/pre-commit.sh` re-checks the intercepted command from the PreToolUse payload, because the `"if": "Bash(git commit *)"` filter fails open on shell compound constructs (`for`/`while`/`if` blocks) — a bare `for f in a b; do echo $f; done` paid a full typecheck + lint + format + unit run. Falls through to running the checks when stdin, `jq`, or the payload is unavailable. See ADR-0015.
- `allowedDevOrigins: ["127.0.0.1"]` in `next.config.ts` — Playwright targets `127.0.0.1` while the dev server's origin is `localhost`, so Next blocked `/_next/webpack-hmr` as cross-origin. Without that socket the Turbopack dev client never boots and the page never hydrates: SSR-presence assertions pass, every interactive e2e fails. Dev-only (`pnpm start` has no dev-origin guard), so CI never caught it.
- `withRollback.ts` now imports `server-only` — it was the one server/node module missing the guard, which is why a stray client-reachable import surfaced as a cryptic `Can't resolve 'tls'` instead of a clean build error. Codified as ADR-0012 (barrels are homogeneous in reach-safety; `server-only` is the enforcement — generalizes the ADR-0007/0009/0011 barrel exceptions into one rule).
- `format:check` (`oxfmt --check .`) no longer trips on gitignored/untracked local files: `.claude/settings.local.json` and in-repo git worktrees (`.worktrees/`) are now in `.gitignore`, which oxfmt honors. Unblocks the commit gate.
- `@/test` barrel no longer re-exports `withRollback`: it was reachable from any Client Component importing `T` (e.g. `GuestbookForm`), and webpack statically resolved its dynamic `import("postgres")` into the client bundle, 500'ing on Node builtins (`tls`, `net`) the browser doesn't have. Integration tests now import it via the deep alias, `@/test/withRollback`. Found by the guestbook e2e (Task 9), the first thing to load a `@/test`-barrel-consuming page through a real Next.js dev bundle. See ADR-0009.
- `.fallowrc.json` used the unrecognized rule name `circular` (silently ignored by fallow 2.104.0); renamed to the valid `circular-dependencies` so cyclic-import detection actually runs.

- Middleware now propagates Supabase-refreshed auth cookies through the next-intl response instead of dropping them (PR #1).
- Node DB scripts (`drizzle.config.ts`, `scripts/migrate.ts`) load `.env.local`, not just `.env` — Next auto-loads it but node scripts do not (PR #3).
- CI `integration` job passes: the workflow now exports `POSTGRES_URL` (the app migrated off `DATABASE_URL`) and `test:integration` gained `--passWithNoTests` (PR #2).
- CI `fallow` job: bumped `fallow` 2.63.0 → 2.104.0 so the binary passes the signature verification `fallow-rs/fallow@v2` requires (signatures ship in 2.77.0+), and set `fail-on-issues: false` so the advisory job (`continue-on-error`) surfaces findings as annotations without failing the check.
- Docs synced with the code: `README.md` (Storybook 10, husky → Claude PreToolUse hook, `.spec`/`.e2e` test taxonomy, five CI jobs, advisory fallow) and `CLAUDE.md` (pre-commit gate runs as a Claude hook per ADR-0006).
